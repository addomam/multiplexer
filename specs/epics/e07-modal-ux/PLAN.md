# E07 — modal daily-use UX

User approves all eight UX recommendations and adds modal navigation. Implement the approved presentation/workflow scope without reopening ACP/ownership requirements. Scope: `../../product/SCOPE_E07.yaml`; impact: `../../IMPACT-E07.md`.

## Modal contract
- Session is the default: native application input, including ordinary Esc/j/k, stays application input. No ordinary-letter global shortcuts.
- Configurable unmodified function key `mode_key`, default F12, enters Menu navigation. Existing Ctrl-letter prefix remains a fallback. F12 is not an ASCII control character but is still an application-bindable terminal escape sequence, not a universally unused/out-of-band key.
- Menu navigation: j/k and arrows select; g/G or Home/End reach ends; Enter opens; i/Esc return; / enters search; n New; s Save project; p Projects; r Rename; x Close; c Control; f explicit Force panel; q Detach; ? help. Destructive close always confirms live work. Existing Ctrl actions remain deliberately supported fallback commands, not required primary actions.
- Search is explicit. Letters including j/k are literal; arrows still select. Enter opens the selected match; Esc leaves search without sending bytes to the application. Paste in navigation is consumed rather than executed as commands; search/form paste remains bounded literal editing.
- A second deliberate mode-key press immediately after entering Menu sends that one reserved key to the same native session via the existing fresh-authority input gate. Repeats/releases do not count as deliberate pass-through. Otherwise Menu mode key returns to the session. No buffered/intercepted input is replayed.
- Forms distinguish input focus from navigation/action focus. Tab/BackTab, mouse, visible action buttons and Escape/back work without requiring Ctrl chords. Text editing never interprets j/k/? as Menu actions.

### Shared interfaces
- Backend config: defaulted `mode_key: String`, F1..F24 (case-insensitive) or `none`; invalid values are rejected atomically. Root client defaults missing old-daemon key to F12.
- Rename: existing `name` operation accepts an exact native terminal or ACP view ID through `terminal`, and a safe `name`. ACP label changes consistently in snapshots/descriptors without a second agent, new tuple or input authority.
- ACP open: optional boolean `new_project` creates an independent unsaved runtime project using the selected source project's directory, no directory creation or inherited hooks; rollback failed opens safely. Existing explicit project placement remains unchanged when false/absent.
- Read-only `project-save-preview`: accepts selected `terminal` or `project`, returns `{project, context}` from the same authoritative cwd/Git-root resolution used by save. `project-save` accepts `expected_context` and rejects a mismatch before mutation.
- ACP metadata/snapshot: `attention` is `{state, questions, permissions}` derived from canonical unsubmitted pending interactions, foreground and lifecycle; codes include `needs-answer`, `permission-needed`, `working`, `cancelling`, `ready`, `finished`, `auth-required`, `starting`, `closing`, `failed`. No content/auth added to ordinary snapshots.
- Project UI: `Dialog::save(snapshot, source, preview: Value)` validates project identity, displays returned context and includes `expected_context` on submission. Existing `manage`, `event`, `refresh`, `failure`, mutable `draw` remain. Structured editing includes name, read-only saved context, hook source/timeout and recipe name/source; Advanced JSON remains optional, not required for these operations.
- Launch UI: `Dialog::new(snapshot, source, catalog, independent: bool)` preserves exact identifiers/options/rejection. Request includes `new_project` only when independent. Mutable `draw` supports painted field/button targets; existing `event` returns None/Cancel/Submit unchanged. Show project/source scope; default basic fields Project/Profile/Name and deliberate Advanced settings. Provide clickable Launch/Cancel/Advanced/Help and Tab access, responsive focused-field scrolling.
- Shared rendering: parent exposes existing `view::button(frame, rect, label, primary)` as pub(super), `view::action_buttons` remains; adds `view::Help::new(&'static str)` for contextual scrollable help. Workers may use these directly; no UI framework.
- ACP UI: existing `new/sync/event/draw/restore_unadmitted` signatures remain. Internal Details/help/action focus and mouse areas must retain rendered target/revision identity before mutation; return unchanged authority envelopes. Existing F-key shortcuts stay as compatibility accelerators.

## Design decisions
No new package [OK: existing Rust/crossterm/ratatui only]. Reason for depth of the small Menu state object: navigation and text entry must be represented separately so identical physical letters cannot accidentally become actions. Existing typed dialog/action patterns suffice elsewhere. Backend additions are minimal UI metadata/placement operations; no new adapter/protocol layer. Implementation is authorized by the user's approval of all recommendations and modal behavior, not by historical Plan/runtime acceptance.
