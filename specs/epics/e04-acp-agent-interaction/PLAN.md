## Research and package choice

- **[OK] `agent-client-protocol-schema = { version = "=1.12.0", default-features = false }`**, Rust ≥1.88, stable wire v1 only. Published `.cargo_vcs_info.json` identifies `e2d83349bc9e28a4059ea3acefa1c91c966f74e2`; source is the official ACP repository. Use its routing enums, payloads, IDs and JSON-RPC envelopes. No copied schema, generic JSON-RPC framework, async runtime, executor, full ACP SDK or SDK process helper.
- Verified signatures: root `ProtocolVersion` (not `v1::ProtocolVersion`); `v1::InitializeRequest::new(ProtocolVersion::V1)`; `NewSessionRequest::new(cwd)`; `PromptRequest::new(session_id, Vec<ContentBlock>)`; `CancelNotification::new(session_id)`; `JsonRpcMessage::<M>::wrap(message)` / `.into_inner()`. `ClientRequest` is client→agent; `AgentRequest` is agent→client. Types are non-exhaustive: use constructors and wildcard error handling, not struct literals or exhaustive assumptions.
- Elicitation: `CreateElicitationRequest::new(ElicitationMode, message)`, `.scope()`; `ElicitationMode::Form(ElicitationFormMode)`; `ElicitationFormMode::new(scope, ElicitationSchema)`; `ElicitationScope::{Session,Request}`. Properties are `ElicitationPropertySchema::{String,Number,Integer,Boolean,Array,Other}`. `MultiSelectItems::{String,Titled,Other}`; single enums use String `enum_values`/`one_of`. Accept content is `BTreeMap<String,ElicitationContentValue>` with string/integer/number/boolean/string-array variants. Construct accept as `ElicitationAction::Accept(ElicitationAcceptAction::new().content(map))`, then `CreateElicitationResponse::new(action)`; Decline and Cancel are unit variants, Accept is not.
- The protocol explicitly says: **“Form support exists only when form is explicitly present and non-null”**, and **“Clients SHOULD validate submitted values before responding”**. Implement all known primitive/enum/multiselect controls, required/optional/default semantics and basic constraints. Explicitly expose any pattern/format constraints not locally checked; never claim full JSON-Schema validation. Agents independently validate. Unknown/future/nested controls are not rendered as known fields and return an explicit error, never coerced data. No general schema-validation dependency is selected.
- ACP v1 `session/prompt` stays pending through tools/questions; no universal turn ID exists on updates. `session/cancel` is a notification, and only the original prompt response's `stopReason: cancelled` confirms interrupt. Every still-pending session permission needs the distinct `RequestPermissionOutcome::Cancelled`, including late arrivals under admitted cancellation.
- `serde_json` gains upstream `preserve_order` / `raw_value` feature unification. Audit its actual lockfile/MSRV and run the complete workspace regressions; never assume the feature change is ACP-local.
- Adapter research only: maintained ACP Codex adapter 2.2.2 (`202e66e63343ec4f5a5e35ab590251d813d129ca`) and Claude adapter 0.94.0 (`7bcbfc7a5ca7ab9c7eece4f0749ccaf49c7ba7e1`, Node≥22). ## Atomic admission and lifecycle algorithm

1. Prepare/validate bounded action data without locks; retain captured target, instance, connection generation, optional exact session, originating control generation, interaction/revision and caller `call_id`. Preparation is not acceptance.
2. Acquire target authority mutex; verify live exact owner/reference/generation. Acquire ACP state second; revalidate lifecycle/identities/capacity/foreground/interaction, reserve all required writer slots and commit immutable work + canonical disposition together. Register outgoing RPC identity before any writer can send it. Publish a memory-only wake flag; release ACP then authority. No socket, pipe, spawn, process probe, wait or join inside either lock.
3. A dedicated writer consumes immutable accepted records without asking whether their old owner still owns the target. Pipe write is `submitted`, not application. A dedicated reader enforces pre-accumulation frame limits, then hands bounded messages to one FIFO application consumer. That consumer never synchronously waits for initialize/newSession/prompt results; inbound forms, updates and exact responses remain processable during those requests.
4. Authority transfer uses the same target ordering point; no ACP actions can be half-admitted across revoke. The ACP work ledger is not `Target.calls` native-input settlement. Outstanding ACP work may cross a safe ACP handoff. Receipt identifies `input-admission` and retained work; no provider-settled assertion.
5. Reserve view/target capacity and initial control before async spawn/handshake publication; publish only while that reserved lifetime is live. A late process/session after close is owned-cleaned, never resurrected. Explicit ACP close commits broker+authority end at the same target ordering point. Existing daemon shutdown ends every live/reserved ACP target with that ordering, then reaps/joins outside locks. Failed capture must not orphan the just-spawned child. Native shell close/remove does not end ACP views. No automatic reconnect or new project-close operation; broader lifecycle UX is user-deferred.
6. Ordered stream closure commits exactly once, marks genuinely unresolved work unknown and releases foreground state. Subsequent local write/error messages may add delivery evidence, never overwrite an observed agent response or turn unknown into confirmed cancellation. Completed protocol responses are not retained forever as outstanding solely because agent application lacks a receipt; keep bounded truthful history/truncation.
7. Explicit cancel against the exact current prompt atomically reserves and commits session/cancel plus Cancelled replies to all pending session permissions, and cancel replies to affected session forms. Already-selected interactions are not answered twice. While cancelling, late applicable requests are atomically admitted nonselectable with those dispositions; capacity failure degrades/fails explicitly. Request-scoped init/auth forms are not silently answered. Only the original prompt's cancelled stop reason confirms interruption.

Tool-call display distinguishes client cancel intent from actual agent tool updates/outcomes: pending tools may show a local “cancel requested” overlay after explicit authorized interrupt, and confirmed prompt cancellation is distinct from proof a tool/process was killed. Never overwrite reported tool result or synthesize completion from force, notification delivery or a local timeout.

## Locks, backpressure and resource budgets

Lock order: **authority → ACP state**. No ACP-state → authority or authority/ACP → daemon topology. Workers emit bounded pending metadata; parent drains it outside broker/authority locks. Snapshot first copies ACP descriptors under daemon topology, releases it, then projects broker metadata. Do not extend the current legacy state-locked snapshot traversal into ACP state or refactor unrelated legacy paths.

Initial fixed budgets (not new persisted config): 8 live/reserved ACP targets globally; 1 MiB per UTF-8 JSON-RPC frame including newline, checked before accumulation/deserialization; ingress 64 messages / 4 MiB; writer work 128 frames / 4 MiB including reserved responses; 64 pending inbound interactions; 64 outstanding outbound RPCs; 64 KiB local prompt/answer content; IDs ≤256 UTF-8 bytes; 64 fields / 256 options per form; 4 MiB / 2048 transcript events per live view; 1024 completed work records; 64 KiB stderr retained while continuing to drain/discard; 8 ended transcript projections with explicit eviction/truncation and no unresolved live RPC eviction. A queue counts in-flight owned messages as well as queued ones. Reserved cancel/error response capacity is accounted in these budgets before acceptance. Maximum metadata/title/error strings are bounded/redacted; agent-provided errors must not leak source content into public metadata.

Exact duplicate detection is bounded separately: 4096 per-instance call-ID tombstones across owner changes, with one reserved final explicit-close admission. Normal actions reject before consuming that last slot; completed-work eviction never enables an old call ID to resubmit. No automatic instance rotation or probabilistic duplicate filter. This concretizes the existing duplicate/capacity requirements without retaining unbounded lifetime IDs.

Oversized/newline-free/invalid UTF-8/malformed transport, unretained inbound requests, or queue exhaustion cannot drop data and then claim continuity/success. Fail/degrade the exact instance, mark affected unresolved work unknown and reap owned resources when the transport is abandoned. Caller admission overflow rejects before canonical commit. Transcript/completed-history caps may evict only completed content with authoritative gap cursors; they may not evict outstanding RPC/interaction mappings. Stalled pipe writes never hold authority/topology/application-consumer locks; close must unblock them through owned cleanup. No transcript clone every TUI frame: use bounded incremental projection by sequence.

Form validation checks type, required fields, UTF-8 character length bounds, numeric finite/integer and inclusive bounds, offered enum intersection, distinct multiselect values/counts and known schema validity. Optional unset differs from false/zero/empty. Default values are editable drafts, never auto-responses. Pattern/format constraints are retained/displayed with an explicit local-validation limitation, not silently certified. Unsupported schema variants return an explicit protocol error and remain inspectable as failure, not a fake question. Never prefetch/open URLs, offer filesystem/terminal delegation or collect authentication secrets through forms.
