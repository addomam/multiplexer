# e04 Build integration contract

Normative companion to PLAN/ADR0004; approved Plan round3. Parent is the only integration owner. First-story local runtime is exercised; implementation acceptance still requires verification and fresh code/security gates. Later-story interfaces below remain the approved target contract, not a claim that those features are implemented.

## Target and ownership variants

- A native PTY stays in `snapshot.terminals`; all old terminal ID resolution, closed request variants, native control receipts and `agent-*` behavior stay intact.
- ACP reserves a separate runtime `agent_views` descriptor `{id,kind:"acp",name,project_id,instance_id,connection_generation,session_id,lifecycle,ownership,seq}`. ID is a fresh `acp-<uuid>`; no fake Terminal, screen, shell integration, process PTY or saved project record. `session_id` is null before session establishment. No invisible replacement/reconnect/reuse of that ID.
- `ownership` on an ACP target explicitly carries `target:{kind:"acp",id}` and `settlement_boundary:"input-admission"`; native ownership keeps the legacy terminal fields/boundary. ACP metadata never asserts provider application settlement. Canonical work lives in the ACP broker, not the PTY `native-input`/forwarding call ledger.
- Existing opaque capability shapes remain exactly `{kind,ref}`. Extend the one `control::Registry` with private `TargetKind::{Pty,Acp}`. Add a concrete `add_acp_target` entry point; do not duplicate claims/force/cancel/conditions. Native `add_target` remains the PTY constructor and native forward paths reject ACP kind.
- `ownership-claim` gains a distinct closed ACP variant: `target:{kind:"acp",id}` **instead of** `terminal`. The same controller/observed/mode/when rules apply. Neither both fields nor a terminal-shaped ACP request is accepted. Existing native variant remains closed and unchanged. All handles are target-lifetime-bound by the registry, not by caller labels.
- ACP receipts, claim-state, controller-private recovery, ownership metadata/events expose the ACP target variant (no fabricated `terminal`). Private controller recovery retains exact current controls and admitted-work identities across socket loss. Decorate safe/force/progress/recovery with canonical retained ACP work and the admission boundary; an empty native ledger is not provider settlement. Public facts have no usable capability references.
- Controller `view` gains a distinct closed ACP variant `{serial,target:{kind:"acp",id},focused}` instead of `{serial,terminal,focused}`. The original persistent amux attachment connection and role checks remain mandatory. A real attachment can select either surface; external callers cannot manufacture native/attachment provenance. Public view facts carry target-kind. Update both focused/backgrounded eligibility and activity/consent provenance to compare the actual selected ACP target (including current `views-backgrounded` predicate), not an absent native terminal field. Conditional ACP keep/withdraw remains human-preserving and policy/timers do not auto-reacquire.

## Local v1 ACP API

All requests use existing `{version:1,op,...}` framing and existing structured errors. Reject unknown fields for these new operations. `persistent` remains a transport field, not authority.

`acp-open` fields: `project` (exact live project ID), optional `name`, optional absolute `cwd` (defaults to project context), `controller` (current registered controller handle), `command` (nonempty argv array, first element absolute executable). Spawn directly, never through a shell. No auto-install, terminal source override, client-supplied environment map, model retry policy or auth credential field. Inherit the daemon launch environment needed by explicitly selected adapter, excluding amux terminal integration/caller-control variables; never publish it. Real harness tests use separately approved private provider roots. A failing spawn cannot leak an owned child.

Open atomically reserves an ACP capacity slot, exact target lifetime and initial controller authority before asynchronous spawn/initialize/newSession. Return `{kind:"acp-opened",target,control,generation,lifecycle:"starting",seq}` promptly. The target object includes `{kind:"acp",id,instance_id,connection_generation,session_id:null}`. Bootstrap progress/errors and genuine request-scoped forms are inspectable. Do not synchronously wait for initialize/newSession inside the caller or application-consumer loop. No hidden startup timeout/cancellation while a user is answering a genuine form; explicit close remains available. Initialization failure/EOF explicitly fails launch and cleans owned resources.

`acp-inspect` fields: exact `target`, optional `include_content` (default false), optional `after` cursor and `limit` (1..128). The exact tuple is `{kind:"acp",id,instance_id,connection_generation,session_id}` (null must match bootstrap). A stale tuple is rejected; snapshot is the explicit resync discovery path. Result contains metadata, current cursor/gap, bounded work/interaction disposition metadata and optional canonical content projection. No raw transport, env, credentials or private controller handle in content/metadata. Read-only inspection never acquires ownership. Include-content is a deliberate local conversation read, not automatic global snapshot logging.

All mutations require exact `target`, current `control`, captured `owner_generation`, and caller `call_id` (nonempty ≤128 UTF-8 bytes; unique per instance). A duplicate ID never resubmits; return duplicate-call and recover through inspect. These fields identify the original deliberate action; the server never substitutes a freshly looked-up control for a stale action.

| Op | Additional fields | Canonical meaning |
|---|---|---|
| `acp-authenticate` | `method_id` | Explicitly choose an advertised agent-type authentication method. Reject unavailable/client-type/terminal/URL methods. Never auto-login, open URLs or collect credentials. Success returns to the pending session-setup state; failure stays inspectable and allows a new explicit method choice. No generic auth integration. |
| `acp-prompt` | `text` | Text-only `ContentBlock`; session must be ready, no active foreground prompt; otherwise busy/not-ready. No steering, auto-cancel or hidden queue. |
| `acp-answer` | `interaction_id`, `revision`, `action` accept/decline/cancel; `values` only for accept | Answer the exact canonical form on this connection, preserving request/session scope. Validate supported content. No fake natural-language question or guessed prompt association. |
| `acp-permission` | `interaction_id`, `revision`, exact `option_id` | Select exactly one offered opaque option. Display actual once/always/allow/reject. Dismiss is not deny; no invented allow-once. |
| `acp-interrupt` | `prompt_id` | Explicit current-prompt session/cancel plus atomically reserved mandatory Cancelled/cancel interaction responses. No implicit interrupt on takeover. |
| `acp-close` | none | End this target/authority lifetime, mark affected unconfirmed work unknown and terminate/reap only owned adapter descendants outside locks. Explicit resource lifecycle, not an interaction deny or confirmed turn cancellation. |

A successful mutation returns `{kind:"acp-admitted",call_id,work_id,state:"accepted",target,owner_generation,seq}`. This is canonical local admission only. Work records retain original controller/generation and related RPC/prompt/interaction IDs, delivery evidence and actual response/error/outcome. `selected` is a local interaction decision; `submitted` means bytes written; `failed` needs actual evidence; application is unknown unless independently observed. Never show `accepted` as task success, agent-applied or confirmed interruption.

Proposed explicit local errors: invalid-request, wrong-target-kind, target-ended, stale-target, stale-control (existing authority errors preserved), stale-interaction, duplicate-call, busy, not-ready, unsupported, capacity-exceeded, transport-failed. No secret/raw-agent error text in public errors or metadata. Preserve structured existing error codes for existing consumers rather than converting them into generic success/unknown.

CLI ergonomics: `amux acp open --project <id> --controller '<handle-json>' [--cwd /abs/path] [--name label] -- /absolute/adapter arg...`; `amux acp inspect '<exact-target-json>' [--content] [--after N]`; `amux acp attach <view-id>`. All other exact operations are available through `amux api '<json>'`. No automatic controller registration/acquisition in a mutation wrapper. Existing `amux attach <terminal>` remains terminal-compatible; ACP attach validates an ACP descriptor. An external opener may explicitly release its initial control before a real attachment acquires it; no external-control masquerade as native human.

## Canonical projections

`inspect` metadata: target tuple, lifecycle (`starting`, `auth-required`, `ready`, `failed`, `closing`, `ended`), advertised agent identity/capability summary, current foreground prompt ID/state, work and interaction IDs/dispositions, cursor/gap/truncation, resource failure category. Authentication methods are explicit safe labels/IDs/type metadata, never tokens or provider paths. Public snapshot/event metadata omits arbitrary backend strings/raw errors/transcript/schema/answers; safe labels are bounded and escape-sanitized.

`include_content` projection is incremental: `{after,through,gap,events:[{seq,kind,...}],interactions:[...]}`. Event categories distinguish user/agent message, thought, tool, plan, completion and error. Do not attach an update to the newest prompt solely by arrival time. Bound transcript/history with gap cursors; no full history clone on each frame. Completed replies can leave outstanding tables while bounded canonical disposition remains visible. Never evict a still-live RPC or pending responder to make room.

Canonical form record: target/connection identity, `interaction_id`, `revision`, inbound typed RPC ID, exact scope, optional tool-call ID, agent identity/message, official schema, supported fields/defaults/constraints and validation limitations, disposition, selected work ID and submission/application evidence. Scope session ID must match the live session; request scope must name a retained outstanding RPC on this connection. A bootstrap request-scoped form may exist while session_id is null. Unknown schema/mode/scope gets explicit protocol error; unadvertised URL mode is -32602. No auth secrets in forms.

Canonical permission record: same identities plus exact session/tool-call ID and offered `{option_id,name,kind}` values. Cancelling-session permissions/forms become nonselectable and commit Cancelled/form-Cancel under the admitted cancel work **before** publication. An already-selected answer is not answered again. Local observer/key/paste events do not manufacture dispositions.

## Backend worker interface (exclusive `src/acp.rs`, `tests/acp.rs`, `tests/fixtures/acp_peer.rs`)

Use the existing serde_json request/projection convention at module boundaries; protocol decoding/encoding inside is through the official typed schema. Concrete broker API, names may only be changed by parent integration:

- `Broker::new() -> Self`.
- `reserve(&self, project_id: &str, name: &str, cwd: &Path, command: Vec<String>) -> Result<Value>` returns the flat reserved descriptor (`id`, `kind`, `project_id`, `name`, `instance_id`, `connection_generation`, null `session_id`, starting `lifecycle`, `seq`). Parent atomically publishes descriptor + registry initial authority before start; rollback both on error. No spawn/probe/I/O under locks.
- `start(&self, id: &str, lifetime: crate::control::AcpLifetime) -> Result<()>` starts asynchronous owned launch/handshake, never waits for initialize/newSession. Parent's concrete cloneable lifetime token exposes `with_live(memory_commit)` and `end(memory_commit)`: both target→ACP; end is system lifetime ending, not owner cancellation. Use it for startup publication and transport failure so a dead target cannot receive a fresh grant; no callbacks into daemon topology. Late startup cleans its own child.
- `prepare(&self, op: &str, request: &Value, controller_id: &str) -> Result<PreparedAction>` captures bounded immutable identities, original server-derived controller ID, client generation/call ID and payload; no authority lookup, leaked capability in metadata or held read lock. Parent obtains controller ID from the already-authorized `Authority::controller_id()`, never a client field.
- `commit(&self, prepared: PreparedAction, checked_generation: u64) -> Result<Value>` revalidates exact lifecycle/identities/capacity/foreground/revision and commits canonical work + reserved egress + registered RPCs together, only inside `Authority::admit_acp`. No I/O/wait/join/probe. Accepted records never ask for a later owner's authority.
- `inspect(&self, request: &Value) -> Result<Value>`; `metadata(&self, id: &str) -> Result<Value>`; `drain_events(&self) -> Vec<Value>` with safe events `{kind, id, data}`; `end(&self, id: &str)` is memory-only closing/unknown/wakeup for parent system-end closure; `cleanup(&self, id: &str)` and `shutdown(&self)` wait/reap/join only outside all authority/topology/ACP locks. Cleanup is real and idempotent, never signal-by-name or killpg after reap. Ended-view eviction emits `acp-removed` so parent can retire matching topology/registry roots. No module-level global service.

`discard_empty_ended(id) -> bool` is a parent-only rollback after outside-lock cleanup: retire only a cleanup-complete ended lifetime with no admitted work, then emit the existing `acp-removed` event to remove topology/registry roots. A concurrent admitted close retains its canonical history; uncertain cleanup remains charged and retained. This is not a general close/removal API.

Parent adds `Authority::admit_acp<T>(&self, end_target: bool, connection: u64, commit: impl FnOnce(u64) -> Result<T>) -> Result<T>`: lock target; require live ACP kind and exact authority; run memory-only broker commit with generation at the same ordering point. Broker independently compares prepared generation. Route `authority.admit_acp(op == "acp-close", connection, |generation| broker.commit(prepared, generation))`. Connection is the real server-stamped attachment connection, never a client field; successful original-human admission records activity under this same target guard, while borrowed controls cannot do so. A successful close ends target authority **before releasing the target lock**. The ending flag is derived from validated server operation, never client classification. Every initial action uses this path. Existing daemon shutdown is the system invoker: after attempting its existing acknowledgement, the stopping path and `Daemon::run` teardown walk all live/reserved `agent_views` through `Registry::end_acp(id, memory_commit)` with target→ACP ordering and no user-control requirement, then reap/join outside locks. Late opens recheck stopping/lifetime and clean their owned child without publication. Force calls neither ending path. There is no project-close operation in this scope.

Each instance owns stdin writer/stdout reader/stderr drainer + one FIFO application consumer, all bounded by PLAN budgets. Reader never uses uncapped read_line/lines or unbounded channels. Writer can block on pipe without blocking application consumer/authority. Application consumer does not wait on another response; it processes initialization/prompt completion, genuine questions, updates and closure in order. Outgoing requests are registered before writer visibility; exact responses survive owner/socket changes. Unknown/unadvertised agent requests get method/params errors, not dropped responders. Session/cancel has no acknowledgement; pending and late permission obligations reserve capacity and canonical decisions atomically. Owned ProcessTree is captured before publishing launch; cleanup owns each child once and preserves unrelated sentinels.

The deterministic local peer is standalone non-production Cargo example `acp_fixture`, source `tests/fixtures/acp_peer.rs`. Parent alone declares it in Cargo.toml; workers do not edit manifests. Build it before selected Cargo integration commands. No libtest stdout banners, nested Cargo build, extra production CLI/debug route, external scripting dependency or raw-stream banner filtering. It independently speaks ACP through actual pipes and supports barrier-controlled real effects, not mock forwarding echoes.

### Concrete projection agreed before worker dispatch

`metadata` and `inspect` share a top-level object: `target` exact tuple, `lifecycle` string, `seq`, `foreground` null or `{prompt_id,state}`, `work` bounded metadata array, `interactions` bounded disposition metadata, `agent` safe negotiated capability facts, `authentication` safe advertised `{method_id,kind}` descriptors, resource/truncation facts. `inspect(include_content:true)` additionally has `content:{after,through,gap,events,interactions,agent,authentication}`. Content `events` have `seq`, `kind` (`user-message`, `agent-message`, `thought`, `tool`, `plan`, `completion`, `error`) and `text` where applicable; tool/plan details preserve their actual categories and optional exact IDs, never arrival-guessed prompt links. Canonical form/permission details are in `content.interactions`, not public snapshot metadata; raw agent labels/errors/schema/answers/auth/environment never leak into global metadata. Work metadata includes original `controller_id`, `owner_generation`, `call_id`, `work_id` and actual retained RPC/outcome identities, never control references.

To keep exact per-instance duplicate rejection bounded after completed-work eviction, retain up to **4096 lifetime call-ID tombstones**, including one final explicit-close slot. Reject normal actions before exhausting that slot; never forget an ID and resubmit it. This cap is separate from 1024 completed work records and applies across owner changes. `acp-close` remains available at the normal-admission cap. No automatic fresh instance, generation reset, retry or probabilistic duplicate filter.

## View worker interface (exclusive `src/tui/agent.rs`)

No socket, subprocess, authority registry or policy implementation. Use crossterm input and the existing ratatui `Frame`/`Rect` drawing conventions; do not introduce a second UI runtime. Concrete `AgentView` owns bounded drafts and incremental cached rendered content. Parent supplies borrowed canonical projection and a captured control/generation receipt when ownership is current. `sync` reconciles exact identity/generation/revision and clears/quarantines stale drafts without replay. `event(&Event)` produces either consumed/local-navigation or a **fully captured** typed action envelope (target, control, owner_generation, call_id, op-specific data), never a reference asking parent to look up new authority. `draw(&mut Frame, Rect)` renders sanitized display data through ratatui. Parent routes the action unchanged through the one ACP daemon path.

Concrete Rust view API: `AgentView::new() -> Self`, `sync(&mut self, projection: &Value, grant: Option<&Value>)`, `event(&mut self, event: &crossterm::event::Event) -> Option<Value>`, `draw(&mut self, frame: &mut ratatui::Frame<'_>, area: ratatui::layout::Rect)`. Grant is a borrowed `{control,owner_generation}` from the original attachment's current receipt, not a lookup recipe. Projection is the exact inspect object above. `event` returns a fully captured action or None for local/consumed input; parent **always consumes active-ACP application events**, never falls through to native input on None. Draft first edit captures tuple/generation/control; identity/revision/authority changes clear/quarantine, no rebind. No optimistic canonical user history. F8 explicitly chooses the highlighted advertised agent auth method; Enter submits reviewed prompt, Alt/Shift-Enter edits newline, Ctrl-C explicitly interrupts the exact foreground prompt. Forms/permission controls join this same state in s02, not fake questions in s01.

Local queue admission is distinct from daemon admission. `NativeControl::acp_action` returns `Result<(), Value>` with the original owned envelope on synchronous busy/full/disconnected rejection. Parent immediately reconciles projection/current grant and invokes `AgentView::restore_unqueued(Value)`. Only a prompt whose original target/control/generation still exactly matches may restore its text and binding; explicit Enter captures a new deliberate action. Never restore/retry an already-queued RPC after transport uncertainty, substitute fresh authority or add optimistic canonical history.

Transient inspect failure retains the last confirmed projection, its history cursor and exact captured draft; show a separate read-error banner, not a false identity/authority change. On a real target tuple change, fetch from cursor0 before reconciling the new projection. Current-grant reconciliation remains independent and still invalidates revoked drafts. A successful deliberate local enqueue clears its superseded local rejection status but makes no daemon/agent admission claim; capture notices remain true after canonical completion.

Human view must show requesting agent, stream categories, lifecycle, owner/observer state, pending question/permission, actual offered scopes, editable defaults and canonical selected/submitted/unknown result. Required/optional unset must remain distinct from false/zero/empty. Support text, number, integer, boolean, titled/untitled single enum and string-array multiselect. Defaults never submit themselves. Enter submits a prompt/permission deliberately; form controls provide explicit review/accept, decline and cancel (document actual keybindings, e.g. F5/F6/F7). Tab/Shift-Tab moves fields, selectors/toggles are deliberate and optional fields have explicit unset. Do not overload Escape/detach/losing focus as deny/cancel. Long content scrolls and untrusted control/escape bytes are rendered as data, never written as terminal commands.

Local keys/paste/edit begin only with captured current authority. Observer keys/paste/mouse/focus do not reach adapter stdin or acquire control; ownership/navigation shortcuts stay separate. Parent intercepts every top-level prefix replay/resize/mouse/paste/raw-key path for ACP, including current double-prefix native forwarding. ACP view focus/activity reports genuine attachment provenance without creating a PTY native-input batch. Parent wires existing warning/keep/withdraw panel and conditional facts. Any new view metadata/actions are agreed with parent before edits; no changes to shared TUI/control files by the worker.

## Parent-only topology and lock integration

Snapshot copies ACP descriptors under daemon topology and releases it before querying broker metadata/authority; never extend legacy snapshot locks into ACP state. No authority/ACP→daemon edge. Drain metadata events and join lifecycles outside authority/ACP locks. Existing daemon shutdown must include all live/reserved ACP views, not just the terminal/codex traversal; saved config and terminal_limit stay unchanged. Native input/execute/screen/resize/close and legacy Codex operations reject ACP IDs/kind without effects. Native terminal close/remove must not end sibling ACP views. User explicitly chose existing explicit ACP close and daemon shutdown; broader project lifecycle handling/UX is deferred, not a private unrouted helper or new public API.

Parent integrates backend and view branches before complete s04 acceptance. Workers skip all tests/build/lint/formatters mid-flight and report exact changes/remaining uncertainties; parent runs verification after integration. User-visible acceptance requires actual CLI and controlling-PTY surface observation, not unit tests or fixture-only claims. Keep tasks failing until their command and intended scenario actually pass; preserve all review failures and unmerged work. Retire only resources created for this work after safe integration. Live provider/auth/model runs and ACP main publication remain gated separately.
