# amux design
## Ownership
Daemon: PTYs, independent emulator per terminal, process cleanup, tree, projects, snapshots and sequenced event ring.
amux owns execution primitives and observations, not autonomous task scheduling, delegation, answer policy or merging. External orchestrators use the same local API; worktree/container/ACP execution providers are not introduced by this reliability cutover.
Client: focused terminal, scroll offset, selection, picker/filter. Ratatui draws a three-row title/tab bar and an edge-to-edge native terminal below it, without a footer. Switch/prefix replaces the surface with a full-screen hierarchical window list and never resizes background terminals.
Background terminals retain their last attached size, initially 80x24. Only opening/focusing/resizing the visible terminal changes its size.
Unix sockets live in a private user-owned runtime directory. API v1 uses bounded newline JSON requests and responses. Same-user control is trusted, not a sandbox. Default one-shot requests close after the response; `persistent:true` keeps the connection for subsequent independently capped frames. Whole-frame request/idle deadline is five seconds, response-write deadline two seconds; no reconnect/replay. The TUI reuses one connection and serializes borrowed input bytes; CLI/integrations keep their one-shot contract.
Automatic startup is serialized per runtime and requires a bounded read-only API-v1 snapshot handshake after initialization; mere socket connectivity is not readiness. Existing incompatible/unresponsive peers are reported, never silently replaced.
PTY readers and writers are per-terminal workers. Native generation and bounded per-row damage generations are published together under that terminal's emulator lock, independently of readers. Screen reads copy only requested cells under that lock. TUI `row_updates:true` requests reconstruct retained rows and prepared styled cells locally; UI dirtiness does not force a full native grid. Input requests an immediate presentation opportunity with 1 ms polling for 50 ms after interaction, returning to 8 ms idle pacing. Up to 32 already-queued events drain before presentation, bounding both input-burst overhead and render starvation. Structured events exclude PTY bytes.
Subscriptions start from an atomic snapshot sequence or explicit sequence. Bounded event retention reports gaps; active waits consume unmatched events. Socket writes occur outside global state locks. Screen updates use emulator generations rather than output events. A screen delta includes `delta`, `base_generation`, `row_indices`, changed `cells`/`lines` and complete cursor/mode/dimension/history metadata. The caller must retain the same viewport with its base generation. Old bases, full damage, scroll/resize/palette/alternate screen or history views fall back to full snapshots. Shutdown disconnects slow request sockets and drains worker ownership, including late PTY creation.
Terminal admission atomically counts live/retained-exited records plus in-flight opens against configurable `terminal_limit` (default 64, range 1–256). Reservations refund on all failed paths; close alone retains the record, while removal frees capacity after cleanup. Partial integration setup and uninstalled PTY children are cleaned on failure. This is not a total byte quota. All diagnostic producers share latest-20 retention and a 16 KiB UTF-8 string cap before event cloning.

The pinned emulator is wrapped at its parsed ANSI Handler boundary: native controls remain forwarded, DECOM CPR subtracts the tracked top margin, and composed graphemes occupy native narrow/wide cells. Ordinary ASCII avoids segmentation/snapshot work except potential keycap starters. Only the final cluster can be replayed when width changes; rollback retains a fixed set of cells and, only for insert/scroll edge cases, an affected row. Additional grapheme working text is capped at 4096 UTF-8 bytes; crossing the boundary starts a new native scalar segment without discarding text. Upstream cell extension storage remains variable-sized, and physical font shaping is not certified by cursor/cell tests.

## Shell and OMP
Stock startup files are sourced through a private ZDOTDIR wrapper. Hooks are appended, not replaced. ZLE descriptor handling performs the final readiness/BUFFER check.
Raw input always goes to PTY foreground. Shell-source execution is a separate request, refused while busy by default; queueing is explicit.
Stock Zsh 5.9 needs a terminal-read wake after a descriptor callback. The adapter samples an input epoch after older input drains, rechecks its native buffer/typeahead, and requests a dedicated private key containing no source. Queued wakes hold the input gate and defer if the epoch changed; immediate execution already owns that gate through acknowledgement. Competing immediate submissions return busy while an earlier submission is pending, preventing gate/descriptor deadlock. Final native readiness precedes top-level source evaluation.
Context capture contains confirmed cwd and exported environment with capture time. Busy-source child launch reports stale capture rather than cloning interpreter state.
OMP extension uses tagged 18.8.7 lifecycle callbacks and local JSON reports. Root status, child status, process lifetime, shell readiness and conversation ID are separate.
Agent finished means an explicit root `agent_end` with matching completed generation and no retry, continuation, question or approval. Cursor-based finish waits require that event, not an idle heartbeat; cursorless waits query the current settled level. Finished does not mean task success. Lost reports/crash become unknown, never successful completion.

## Projects and Git
Start unsaved with a main host shell. Only its confirmed cwd updates context (repository root if applicable); each other terminal retains its workspace.
Saved project IDs persist with configuration only. Save resolves the latest confirmed main-shell cwd/repository root outside global locks before persisting; an explicit re-save updates that location. Organizational tree is independent of process ancestry; reject cycles and cross-project parenting. New terminals choose their default main parent atomically at publication, independently of capture source. Concurrent project opens reserve creation so hooks run once.
Configuration uses canonical target identity and a stable private sibling lock, nonblocking acquisition (`config-busy`), exact loaded-byte comparison (`config-conflict`), private temp-file sync, atomic replacement and containing-directory sync before acknowledgement. A stale store does not overwrite newer settings or saved projects. Post-replacement sync failure leaves the old expected generation and reports reload guidance; no live full-config reload or uncooperative-editor serialization is provided.
Removal performs process cleanup outside the tree lock, then removes the current Entry and rewrites its children atomically; an earlier snapshot's ancestry is never reused. This prevents concurrent removals/reparenting from publishing dangling parents or cycles.
Git cache key includes actual workspace, canonical Git/worktree directory and repository identity, not branch. Refresh off the PTY path; bounded cache pins active workspaces and evicts inactive entries. Clock-only cache age changes do not create state events.
Hooks: daemon-start once, project-open once per open, never reattach. One bounded worker runs startup then project jobs, in configuration order. Cwd is the daemon initial directory or project context; environment is inherited exports. Per-hook timeout; bounded stdout/stderr in snapshot diagnostics and sequenced events; failures do not suppress a usable shell. Shutdown cancels/kills/reaps the active hook's owned process group and skips pending jobs. Cancellation is distinct from timeout.

## Modules and depth
runtime: owns PTY/emulator/process lifetime; hides OS cleanup and threading from clients.
Cleanup validates kernel birth identities before signals, freezes/rescans descendant producers, sends TERM/CONT with a grace period, then freezes/rescans and KILLs. Natural exit records descendants before reaping the original root. Freeze waits are bounded; OS permission changes/uninterruptible I/O and already unobserved orphaning remain explicit limits.
integration: owns shell-safe structured submissions and lifecycle reporting; hides handshake/readiness races.
projects: owns persistent configuration, hooks and Git cache; isolates disk/Git work from terminal I/O.
client: owns local request framing; same contract for CLI, extension and TUI.
tui: owns input translation and view state. Private tui/view caches one bounded prepared Ratatui Buffer: decode validated changed rows once, rebuild on full snapshots, copy bounded rows for drawing, apply selection only to the destination, and use authoritative cursor/mode metadata. Wide glyph clipping and style clearing preserve native presentation; rejected deltas change neither cache nor retained JSON. Ordinary widgets draw chrome/list/exit card; shared geometry supplies drawing and mouse hitboxes. Exited windows show actual code and remove/new actions; New retains the old record and captured source context. Closing the last record shows explicit New/Exit actions; exit detaches without stopping the daemon. Empty-state behavior requires no active target and no records, so a stale startup snapshot does not steal fuzzy-search keys. Full-surface copying/diff and full-damage transfer/rebuild remain performance limits; no optimistic local echo.
No generic plugin layer, distributed service or recovery journal.
